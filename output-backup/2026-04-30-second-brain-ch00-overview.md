# 今の外部脳の仕組み

## Obsidianって何？

ひと月ちょっと前まで、Obsidianというアプリの名前すら知らなかった。

そもそも普段のテキストの読み書き量がしれている。プライベートで使ってるMacBook Airは仕事には一切使わないので、ネットサーフィン、Cubaseでの音楽関係、あとロードスター買ってから撮り始めたドライブ動画の確認程度。そもそもテキストファイルを扱う機会は皆無に近かった。マークダウン？なにそれ。フォルダ階層をどう設計するとか、ノートをどうリンクさせるとかいう発想。。というかそもそもそういう作業の存在を認知してなかったというのが正しい。

それが、知人から「これ使ってみて」と渡されたAI関連のシステムをきっかけに、ひとつ入れて、もうひとつ入れて、流れでそのまま今日まで来てる。気がついたら、自分のMacBookの中で、AIと連携した仕組みが何個か並列で動いていて、自分はその上に乗っかって週末に文章書いたりWebサービスいじったりしてる。

知らなかったとも言えるし、必要なかったとも言える。とにかくAIとの付き合いが深くなる前、少なくとも自分の世界には必要ないというか認識すらしてないツールなので一切触ってなかった。

このシリーズで書くのは、それがどういう構造になってるかの自分の作業環境の現状説明。中身がどう積み上がっていったか、どんな仕組みになっているかは、順次書いていくつもり。もちろんAIに解説を丸投げしながらw
今回は、まず手元で何がどう繋がってるかだけ、現在の全体像を説明しておこうと思う。

先に言っておくと、これは完成されたノウハウとかじゃなくて、AIと一緒に外部脳を作り始めた人間の作業ログ。完璧な解説記事として読まないでほしい。

もし興味が湧いたら是非このシリーズを楽しみにして欲しい。

## 中央にVault、その周りに全部

<!-- 全体図: Obsidian Vault を中心に、3リポ（Event/Magi/Meta）+ ClaudeChat + Codex + 連携外 ChatGPT/Gemini + 自動取り込み（MD/画像/音声(半自動)）+ HandOff + Webサービス支援層（GitHub/Vercel/Supabase 等）-->

ど真ん中に置いてあるのが、Obsidianの「Vault」と呼ばれるデータ置き場。Obsidianのアプリ内用語だと保管庫。要するにマークダウンファイルが大量に入ってるフォルダなんだけど、これが各方面と繋がっている。
あ、そうそうそのObsidianは外出先でiPhoneやiPadでも使う関係でiCloud上においてある。

その周りに、自分の作業環境であるリポジトリ（コードを置く箱、以下リポ）が3つ並んでいる。Webサービスを作ってるリポ、note記事を作ってるリポ、その2つの上から見渡すためのリポ。それぞれのリポの中ではAIコーディングエージェントが住み着いていて、自分はその子達と会話しながら手を動かしてもらう。

リポの外には、別系統のAIが何種類かいる。VaultにファイルをポンとIN/OUTできるやつ、ChatGPTやGeminiみたいに完全に外側で会話してるけどダウンロードしたファイルが結局Vaultに合流してくるやつ。系統が違うだけで、最終的にVaultが受け止める。

さらに、Webサービス側を支えるGitHubとかVercelとかSupabaseとか、そういうSaaSが外周に並んでいる。これらは外部脳というよりは作業の足回り。図に出てくるのはここまで。

## 各セクションの中身

中央広場と外周だけ見せても何の話かわからないのでそれぞれもう少しだけ寄ってちょっとだけ解説してみる。

### リポとVaultの関係

<!-- 詳細図3-1: 3リポ（Event/Magi/Meta、各リポは AI コーディングエージェント作業環境）と Obsidian Vault の関係。symlink でリポから Vault を参照、各リポは Vault を共通の中央広場として使う -->

リポは3つあると書いた。Eventと呼んでるリポがWebサービスの本体で、これはこのnote記事に制作過程をシリーズで書いている「24offmap.jp」を作ってるところ。Magiと呼んでるリポはnote記事を生成するためのヘルパーエージェント。Metaと呼んでるリポはその両方に属さない話題や作業、または上から眺めて、両方にまたがる事項、運用ルールとか引き継ぎ仕様とかを決める作業場。形になってないアイディアの壁打ちをして相談する場所でもある。上からと言っても運用上の話なだけで構造上は他の２つと同列。自分が利用方法としてそのような役割にしているだけ。

3つともObsidianのVaultに繋いである。といっても、Vaultの中にリポを引っ越したわけじゃない。リポ側にある各リポの設定ファイルで「Vaultはあそこにあるよ」と明示しているだけ。これでリポの中で動いてるAIが「Vault側のあのファイル読んで」「あそこに書いて」をできるようになる。

中央広場として機能していて、ナレッジを置くのも、引き継ぎを置くのも、構想を置くのも全部Vault。リポ単独では完結しない設計になっていて、これは結果的にそうなった。最初から狙ったわけじゃない。

### AIの編成

<!-- 詳細図3-2: AI編成3層 + 経路差。リポ内 Claude Code / Vault連携 ClaudeChat・Codex（Codex は直接参照、ClaudeChat は方向で経路違い: Chat→Vault は DL→自動取り込み、Vault→Chat は chat-bridge→Google Drive コネクタ）/ 連携外 ChatGPT・Gemini -->

MacBook内住んでるAIはいま4種類いる。立ち位置で3つに分かれる。

一番メインで動いてるのが、各リポの中に常駐してるClaude Code。常駐って言い方が正しいかわからんけど、それぞれのリポに専属のエージェントがいる。コードもnote記事の下書きも、実装作業はだいたいこいつらに任せてる。Webサービス側のリポにはWebサービス側の、Magi側のリポにはMagi側の住人がいて、頭の中身は同じだけど見てるものが違う。

そこから一段外側に、Vaultと連携してるAIが2種類いる。

ひとつはClaudeChat。Claude Code同じ会社の同じAIみたいな顔してるけど、全然別物で、同じアカウントで使ってても双方の情報連携とか皆無。外出先でChatでアイディア壁打ちして、いざ実装・・となっても、Code側には何も伝わってないので、明示的に情報の橋渡しをしてやる必要がある。アプリではクリック１つで切り替えられるのに不便だよね・・・ちなみにこの橋渡しは方向で経路が違ったりして地味に複雑なので、別の章でちゃんと書く。

そしてもうひとつは数日前から品質保証担当として呼んだCodex。こっちはVaultを直接参照できる。先日「AIにディスクを64GB食われた話」を別記事で書いたのだけれど、あの時の容疑者本人だ。容疑者っていうか犯人ね。事件のあと反省してたみたいなので起訴猶予扱いにしたので今のところ元気に働いてくれてる。
<!-- リンク設定: 「AIにディスクを64GB食われた話」に「AIが暴走したっぽいのでAIに捜査させたら犯人が特定できた」のURLを設定 -->

さらに外側、Vaultとは一切繋がってない別世界にChatGPTとGeminiがいる。完全に別利用。連携してない。ただし、彼らとの会話の結果として手元にダウンロードしたMDやPNGは、後述する自動取り込みで結局Vaultに着地する。連携外のまま、素材だけ後ろから合流してくる。
あ、PNG(画像素材）はVaultじゃなくてVaultの外にあるiCloud上のフォルダに自動保存ね。
理由はまた別で。

```
[内側] リポ常駐AI
   ↓
[中間] ClaudeChat / Codex（Vault直結）
   ↓
[外側] ChatGPT / Gemini（DL経由でVault合流）
```

役割もキャラも違うので、用途で使い分けてる。どれが優秀とかは、たぶん意味のある問いじゃない。

### ダウンロードフォルダの自動仕分け

<!-- 詳細図3-3: 自動取り込み3系統（MD / 画像 / 音声(半自動)）。MD・画像は ChatGPT・Gemini・ClaudeChat 等からのDLファイルが対象。音声は外出先メモ → 帰宅後にMacで処理 -->

これがあると無いとでだいぶ違う。

ChatGPTとかClaudeChatとかGeminiで会話して、結果をMDでダウンロードする。普通にMacの「ダウンロード」フォルダに落ちる。落ちたあと、特に何もしない。スマホでiPhoneを開いてObsidianを覗くと、数秒後にはVaultの構想置き場にそのファイルが入ってる。

なぜそんなことになっているか？これは意識低い系おじさんならではのものぐさの発想の賜物。そもそもなんでMDをこんなに多様するようになったかはシリーズ中のどこかで説明するけど、どのAI使っていても、一段落した段階で内容のサマリや決定事項、要注意事項等をまとめてMD（マークダウンファイル）でまとめるようにしている。基本的にClaude CodeやCodexのようにコーディング系エージェント以外Chat系AIは直接ファイルの読み書きができないので作ったファイルを指定のフォルダに格納とかはできない。作ったファイルをチャット画面上にダウンロード可能な形で表示するだけなので、ユーザーが手動でダウンロードして適切なフォルダに保存する必要がある。でもめんどくさいじゃん？結果、2026mmdd_xxxxxxxx.mdみたいなファイルがどんどんダウンロードフォルダに溜まっていくことになる。ある程度貯まると中身確認して適切なフォルダに保存するとか絶対やらなくなる。じゃぁ「ダウンロードフォルダ監視してファイルが落ちてきたら自動で適切なフォルダに移動させられないの？」ってAIに聞いたら「できます」っていうので作ってもらったの仕組みがこれ。

仕分けは3系統。MDが構想置き場、画像が画像置き場、音声がボイスメモ置き場。MDと画像はAIから出てきたダウンロードファイルが対象、音声は外出先でiPhoneやApple Watchで撮ったボイスメモが帰宅後にMacのフォルダに落ちて、それを処理する。音声だけは最後の1ステップが手動で残ってるので半自動。

中身がどうなってるかは、ファイル名のパターンで仕分けてるらしい、くらいの理解で使ってる。たまにファイル名規則から外れたものが落ちてきて素通りすることはある。その時は、自分で然るべきフォルダに突っ込めば終わり。

### 引き継ぎ（HandOff）

<!-- 詳細図3-4: HandOff フロー（セッション間 + リポ間）。Vault の _handoffs/ にMDで状態を残し、次セッション or 別リポAIが読み込む -->

最近はどのAIも記憶（メモリ）を実装して、ある程度は記憶を持っているので実はここまでの情報共有の仕組みはいらないんじゃないか？とも思ってるただ、コンテキストが肥大化すると（１つのチャットが長くなってスクロール量が多くなる状態）そのメモリが怪しくなってくるし、肥大化したセッションの後に始めた新規セッションで「さっきの話の続き」をしようと思ってスムースにシームレスにできるのかどうか、、、、、というわけで、セッションが大きくなってきた段階で早めに新しいセッションに移ることにしてる。その際必ず引き継ぎ資料を作らせて次のセッションに渡す仕組み。「AIのメモリに過度な期待をせず外側にメモを残しておけば事実上記憶を持ってるのと同じになる」だと感じている。

その仕組みの名前を、勝手にHandOffと呼んでる。やってる事自体は単純で、セッションの終わりにそのAIに「ここまで何やったか書いておいて」と頼んでMDファイルを残してもらう。次のセッションで別の自分（あるいは別リポの住人）が立ち上がったら、まずそのMDを読み込ませる。それだけ。ちなみにこれは先に書いたチャットのMDファイルのDLと違ってClaude Codeが作成した引き継ぎファイルを指定フォルダに配置してくれて、新セッションの立ち上げ時は引き継ぎファイルがどこにあるかを把握するよう設計してある。ユーザーは「セッション新しくするから引き継ぎよろしく」と言って引き継ぎプロセスの完了を待って、新セッションを立ち上げるだけ。

これでセッションをまたいだ作業の連続性が出る。さらに、リポの外側で動いてる別系統のAIにも同じMDを読ませれば、別の脳に同じ続きをやらせることができる。前述の64GB事件で、Claude側で詰まった調査をCodexに引き継いだ場面があったが、あれも要するにこれの応用。
<!-- リンク設定: 「前述の64GB事件」に「AIが暴走したっぽいのでAIに捜査させたら犯人が特定できた」のURLを設定 -->

そんなに高度な仕組みじゃない。けど、セッションが終わるたびに記憶が怪しくなるあの感覚を抑え込めるのは大きい。

## 動いてるところを3つ

抽象的な話ばかりだとピンと来ないと思うので、実際に体感として見えてるものを3つ挙げる。

ひとつめ、ダウンロードファイルの自動格納。ClaudeChatでブレストして、結果をMDでダウンロード。Macで何もしないままiPhoneのObsidianを覗くと、Vaultの構想置き場にもうそのファイルがいる。最初にこれを見たときは、画面のあちら側で誰かが走り回ってる絵が頭に浮かんだ。実際には誰も走ってないけど、体感はそう。

%%MacBookの中で誰かがファイル持って走り回ってるコミックふうイメージ%%

ふたつめ、音声メモ。出先でiPhoneやApple Watchに思いついたことを吹き込む。喋りかけた本体はiPhone側のボイスメモにファイルとして残る。帰宅してMacを開くと、文字起こしされて、テーマ別に振り分けられて、Vaultの中で然るべき場所に落ち着いている。CarPlay接続中はiPhone本体のマイクが車側に持っていかれてうまく拾えない、という細かい罠もあったけど、Apple Watchで利用することで、ドライブ中のひらめきもその場で捕まえられるようになった。

みっつめ、HandOff。セッションを切り替えた後最初に「引き継ぎ確認」と最初に頼む。すると数秒後に「あ、前回ここまでやってたんですね、続きから入ります」と返ってくる。冷静に考えれば裏で単にMDを読んでるだけ。なのに体感としては、前のセッションの記憶を持ったまま戻ってきたみたいに見える。会話相手としての連続性は、ちゃんとある。

## なぜObsidianに行き着いたか

ところで、Obsidianを入れる前のBeforeはどうだったか、と書こうとして手が止まった。

Beforeがそもそも無い。

最初に書いたようにObsidianを入れる以前の自分は、テキスト情報を頻繁に読んだり整理したりすること自体、ほぼやってなかった。マークダウンファイルを大量に管理する必要が出てきたのが、ほぼ同時にObsidianを入れた瞬間で、それより前にはそういう生活が無かった。だから「Obsidian導入前 vs 導入後」みたいな劇的な比較ができない。

きっかけは、知人から譲り受けたnote記事生成のシステムだった。AIが構成や下書きを作ってくれるんだけど、出てくる中間ファイルがマークダウンで、しかも段階ごとにフォルダ分けで保存されていく。これを見るのも直すのも、毎回「フォルダを開いて、ファイルをクリックして、メモ帳で開いて」をやるはずだった。考えただけで面倒くさい。それを使うために入れたのがObsidian。

入れてみたら、メニューとビューワーとエディターが一個のアプリの中で完結してて、マークダウン記法の段落とか強調とかが視覚的にちゃんと見える。MDをまとめて扱うには、想像してたより圧倒的に楽だった。さらにVaultをiCloudの上に置いておくと、iPhoneとiPadからも同じファイルが触れる。これは出先で思いついた時にデカい。

ただし欠点もちゃんとある。VaultをiCloudに乗せた副作用で、MacBookのFinderからファイルが普通には見えなくなった。Obsidianの中では当然見えるんだけど、たまに別アプリにファイルをコピーしたい瞬間に「あれ、Finderに無いな」と詰まる。手放しで万歳というほどではない。

なぜそこに行き着いたかの細かい話は、また別途書く。今回はここまで。

## ここまでの構築にひと月ちょい

時系列だけ並べておくと、Obsidianを入れたのが2026年3月後半頃。今が4月末。

その間の出来事として、Vaultをセットアップして、過去のAI会話を集約して、リポからの参照経路を作って、ダウンロードフォルダのウォッチャーを設定して、HandOffのテンプレートを整備して、別系統のAIをVaultに繋いで、Codexを呼んで、音声メモの経路を試して、3つめのリポを切り出して、というのがあった。書き出すといかにもいろいろやってるけど、実装してるのは全部AIで、自分は「これやりたい」「ここ違う」「これは要らなかった」を判断してるだけ。

何かを掘り下げて深く理解した1ヶ月、ではない。手数を使って試して、動いた仕組みは残し、動かなかった仕組みは削った1ヶ月。残った形が、いま書いた構造。
そもそもこれをやってる意味がどこまであるのかもわからない。もしかしたらClaude ChatやClaude Codeの使い方次第でここまで複雑な仕組み作らなくてもやりたい事は実現できて無駄な事をやってるかもしれない。この仕組みのせいでClaude Codeのパフォーマンスの足枷になっていて、無駄なトークン消費を発生させてる可能性もある。
ただ、独学で一歩一歩使ってる中で不便に感じた部分（特にAIの記憶や情報の保全、共有）について自分なりに補完する仕組みを作っていった結果が今の仕組みになっている。
「おーなるほど！」って思う人もいるかもしれないし「何無駄なことやってんの？バカじゃね？」って考えもあると思う。前者の方はぜひコメントで感心した気持ちを書いてください。本人が喜びます、後者の方はコメントには書かず静かに生暖かく見守ってください。本人が落ち込まずに済みます。

さて、ここから先は、その積み上がりを順番に紹介していこうと思う。最終回は決めてない、書いてる最中に新しい仕組みが増えていく可能性もかなりある。

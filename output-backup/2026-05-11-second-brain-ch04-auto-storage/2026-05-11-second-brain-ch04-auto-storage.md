## 【劣化した脳をAIで補完】日々作られるファイルを自動で整理

前回まででObsidianとMagiの便利さは書いた。テーマだけ投げれば下書きが立ち上がるとか、裏でAIが材料を拾ってくるとか、気をつけないと手を抜くとかそういう話。

まだ読んでない方はこちらから
[🔗 章1「なぜobsidianを選んだのか」のリンクをここに設定]

ただ、それが成立してるのは、Magiが拾ってくる材料が、ちゃんとObsidianの中に「溜まってる」からだ。今日はその「溜まってる」状態が、どうやって出来上がったのかという話をちょっとだけ。この仕組みを思いついて、AIと作り上げた日がいまの作業環境の中で核になる一番濃い一日だったかもしれない。

---

## 量産されるファイルたち

ObsidianとMagi一式を入れて、使い始めた頃にちょっと嫌な予感がしてきた。

AIと作業してると、毎回MDファイルがダウンロードフォルダに落ちてくる、というか、Claude Code以外（今ではCodexも）のチャット型AIは、チャットのまとめ、作業ログ、別のセッションでの会話のエクスポート等AIで作成したファイルはユーザーがダウンロードしてファイルとして保管するしか基本的に方法がない。もちろんダウンロード保管時にまめにファイル名をつけて、決めたフォルダに保管すればいいんだけど、意識低い系おじさんがそんなこと出来るはずない。少なくとも継続してやり続けるのは無理だ。Macのダウンロードフォルダにxxxxx.mdってファイルがどんどん増えていくのは容易に予想できる。

普通なら、というかきちんとした人なら、上に書いたようにDL毎にちゃんと仕分けるだろうし、ちょっとマメな人なら「毎週末ちょっとずつフォルダ分けして整理する」という運用に入るんだろう。でも意識低い系おじさんは違う

いかに~~楽に~~便利にするかを第一に考える。デイリーやウィークリーで整理する自分の姿が想像できない、正確には、長くても数週間で投げ出す姿が容易に想像できる。そして溜まり続けるMD。。。

そこで当然の帰結として「自動化」をAIに相談することになる。

散らかったファイルの手動での振り分けは毎日だろうと週一だろうと分には続かない。だったら、「散らかる前に勝手に整理される」仕組みを作ればいや作らせれ・・・作って貰えば楽だ。手で振り分ける時期を一切経由せずに、最初から自動化したい。

 AIを使うといろんな事が実現できる。AIを活用する一番のコツは実現したい何かを「発想」することかもしれない

## 仕組み作り開始

というわけでClaude Codeに相談を始めた。

最初は例によってディテールなくこんな話。「このプロジェクトでやってることを定期的にObsidianに自動で投げ込みたい」「チャット履歴もセッションのまとめも、AIと作ったソースも、全部勝手に入っていく仕組みがほしい」と。

ここで、Code側で扱っているファイル（プロジェクトの中で動かしてるソースとか、Codeが作ってくれたメモとか）は、話が早かった。これはCode自身がObsidianのVaultに直接書き込む方式に落ち着いた。Code側のプロジェクトとObsidianのフォルダを最初から重ねておけば、Codeがファイルを保存した瞬間に、もうそれがObsidianの中にいる、という形になる。Gitフックで同期するのはどうですか、みたいな提案も途中で出てきたけど、最終的にはこの「もう同じ場所に書く」というシンプルなやり方に落ち着いた。気がつくと、Codeで作ったメモやスクリプトは何もしなくてもObsidianの中に並んでいるようになっていた。

問題はもう一方だった。Chat側のClaudeで作ったまとめ、ほかのLLMで吐き出したログ、AIに作らせた画像。こっちはCodeみたいに「Obsidianに直接書く」ことができない。Chatでは、Claudeがアーティファクトを作ってくれて、自分がダウンロードボタンを押して、Macのダウンロードフォルダにファイルが落ちてくる、というプロセスを踏むしかない。間に「ダウンロードフォルダ」というワンクッションが挟まる。ここをどうにかしないと、結局散らかる。

例によって、何をどうして欲しいじゃなくて、実現したい事をAIに聞いてみる

「ClaudeでのまとめをファイルとしてDLして指定したフォルダに置いたら、そのファイルをバッチとかでいじるようなことはできない?」

決して「ダウンロードフォルダに落ちてきたMDファイルをバッチ処理してフォルダに振り分けるようにして」とは頼まない。この違い理解して意識しておくのはAIと付き合う上では非常に大きい。この考え方については以前番外編③でも書いた

[🔗 番外編③「自己紹介編」の埋め込みリンクをここに設定]

Codeから返ってきたのは「macOSのlaunchdで実現できます。Downloads/を常時監視して、ファイル名のパターンにマッチしたらObsidianの指定フォルダに移動する仕組みです」

launchdが何なのかもよく分かってないけどCodeの説明によるとMacを起動するたびに裏で勝手に動き始めるやつ、ということらしい。「そもそもこのバッチをダウンロードフォルダのファイル監視で自動化できない?」と続けて聞いたら、「fswatchというツールをインストールして、launchdで常駐させましょう」と返ってきた。

fswatchも、Homebrewも、よく分かってない。分かってないままだけど、Codeが「これとこれ入れてください」と順番に出してくるので、言われた通りに打ち込んでいった。

ところがこれについて詰まることになる。

## 全てCodeに任せて・・とはいかず

基本的に、こういうセットアップは Code にほぼ全部任せている。スクリプトの作成も、設定ファイルの調整も、サービスへの登録も、Code が手元のファイルを直接書き換えて進めてくれる。自分のやることは、Code が何か言ってきたときに「OK」「だめ」と返すくらい。意識低い系には極めてありがたい仕組み。

ただ今回ひとつだけ例外があった。fswatch というファイル監視ツールのインストールだけは「sudo の権限の関係で自分（Code）からは実行できないので、手動でお願いします」と言われた。要するにシステム側を触る権限が Code に渡ってないので、ユーザーが代わりに打つしかない、ということらしい。

仕方ないので Code に言われたコマンドを打った。途中で「動かない」「だめ」とだけ伝えると、設定ファイルを書き換えて Code 側で対応してくれた。何が起きていたのかは正直よく分かってない。ただ、書かれた通りに打っていると、しばらくして動くようになった。

## なんとか完成

テスト用のMDファイルをダウンロードフォルダに置いてみる。

数秒後、ファイルがダウンロードフォルダから消えている。ObsidianのVaultの中を覗くと、所定のフォルダにそのファイルがちゃんと入っていた。

「入った！」

Codeに、それだけ返した。構想から壁打ち、実装までほぼ丸一日かけて、なんとか思った通りの仕組みが動いた。

完成した流れは、こんな感じだった。セッションの終わりにClaude（Chat側）に「まとめて」と頼んで、Claudeがその日のまとめをMDで出してきて、ダウンロードボタンで保存する。そこまでは普通の操作。そこから先が勝手に動く部分で、MDが落ちた瞬間に裏で待機していたやつがファイル名を見て、Obsidianの所定のフォルダに移動させる。自分は何もしてない。

その日はそのまま勢いで、もう一個作ってもらった。Claudeの会話履歴をまるごとエクスポートするとZIPが落ちてくるんだけど、そのZIPを自動でばらしてMD化してObsidianに入れる仕組み。Codeが「ZIPが落ちたら自動で変換して保存するスクリプトも作りますか」と提案してきて、「やろう」と答えたら出来上がっていた。

完成後にテスト用のエクスポートZIPを試しに置いてみたら、38本の会話が全部MDに変換されてObsidianに入っていた。Codeが「38件の会話を検出・変換、スキップ0件」と報告してきた。なかなかいい仕組みができてきてる気がした。

ほぼ一日かけてCodeで作ったメモやスクリプトが何もしなくてもObsidianに並ぶようになり、ダウンロードしたMDが自動でObsidianに入るようになり、ClaudeのエクスポートZIPまで自動でMD化されるようになった。意識低い系のおじさんがAIに教わりながら一日で組み上げた仕組みとしては、まあ上出来だったと思う。

## ただ、全部「同じ箱」に入っていた

しばらく使っていて、次の問題が出てきた。仕組み作ってから数週間くらい経った頃だったと思う。

ダウンロードしたMDが自動でObsidianに入る、までは出来ていた。ただ、入る先が「ひとつのフォルダ」だった。Obsidianの中にセッションまとめ専用みたいなフォルダがあって、ダウンロードしてきたMDは全部そこに入っていた。

何が問題かというと、ダウンロードしてくるMDは、実は何種類かあった。その日のセッションの全体まとめもあれば、思いついて吐き出したアイデアメモもあるし、喋ってる途中で「あ、これは決めごとだな」と意思決定として残したメモもある。「これ次のnoteのネタにしよう」と思って起票したやつとか。

それが全部、同じ箱に流れ込んでいた。

数日経つと、フォルダを開いてもどれが何なのか見分けがつかない。ファイル名は同じパターンで揃っているし、中身を開かないと何の話か分からない。沼の場所がダウンロードフォルダからObsidianに移動しただけで、本質的には何も解決してなかった。

これもCodeに相談してみた。提案してきた解決法はシンプルで、「ファイル名のパターンで振り分け先を変えればいい」というものだった。

セッション全体のまとめならこの名前で、アイデアメモならこの名前で、意思決定ならこの名前で、ネタ起票ならこの名前で、と、ファイル名の頭の部分で「これは何のMDか」を分かるようにしておく。自動で動いているウォッチャー（振り分けスクリプト）がファイル名の頭を見て「これはアイデアだからこっち」「これは意思決定だからあっち」と分けて入れる、という仕組み。ファイル名が「行き先の指示書」を兼ねる、という設計だった。

ただ、ファイル名のパターンを毎回自分で考えて打ち込んでダウンロード、なんてやってたら結局手間が増える。ここがちょっと面白いところで、ファイル名はChat側のClaudeにつけてもらえばいい、ということになった。Chat側で「ネタとして起票して」と頼めば、Claudeが「これはネタだな」と判断してネタ起票用のファイル名で出してくれる。「これは決めごとだから残して」と頼めば、意思決定用のファイル名で出してくれる。
実運用上はそこまで厳密に頼まなくても、Claude Chat側で「Ideaとして残します」とか「決定事項でいいですか」とかある程度判断して提案してくれる

自分は、いつもどおり喋って、「これ残して」と頼むだけ。Claudeが名前を決め、ダウンロードしたら裏の仕組みが名前を読み取って、それぞれの行き先に流す。Chat側のClaudeが「これは何か」を判断して名付け、裏の仕組みが「どこに入るか」を担う。役割分担としてはそういう形に落ち着いた。

## MDができるなら画像も？

ここまでで、MDファイルは大体片付いた。ただ、もうひとつ気になり始めたものがあった。AIに作らせたPNGの画像ファイルだ。

note記事用のサムネをClaudeやらほかのLLMに作らせると、PNGが出てくる。これもMDと同じで、ダウンロードボタンを押して保存するしかない。気がつくとダウンロードフォルダにAI生成のPNGがいくつも転がっていた。これも見分けがつかなくなる前に振り分けたい。

ここでひとつ厄介な事情があった。ダウンロードフォルダに落ちてくるPNGは、AI生成のものだけじゃない。スクショもあるし、誰かから受け取った画像もあるし、ウェブから落としたものもある。MDと違って、PNGには「これはAI生成です」というファイル名の規則がない。ファイル名だけで判別するのは無理だった。

これもCodeに相談したら、PNGの中身を見てAI生成かどうかを判定するスクリプトを書いてくれた。画像のメタデータからどのAIが作ったものかある程度判断できるらしい。試しに各AIからPNGをダウンロードして確認してもらったら大丈夫っぽい確認が取れた。これでダウンロードフォルダに落ちたPNGをこのスクリプトに通して、AI生成と判定されたものだけを所定のフォルダに移す、という仕組みができることになった。

画像ファイルの自動格納については一つだけMDファイルとの違いがある。AI生成と判定された画像の格納先は、Obsidianの中じゃなくて、Obsidianの外側のiCloud直下にフォルダを作ってそこに入れることにした。画像ファイルはnote投稿時にアップロードする必要があり、そのためにはMacのファインダーでファイルを選択できる必要がある。Obsidian導入の記事で書いたようにモバイル版のobsidianアプリと連携する関係でobsidian VaultはMacのファインダーでは中を見ることが出来ないモバイル版のobsidianで作ったフォルダを使っている。それでは不便なのでobsidian管理下ではなくicloud直下にフォルダを作ったというわけ。

これでPNGも、ダウンロードボタンを押した数秒後にはダウンロードフォルダから消えて、AI生成と判定されたやつだけがiCloudの所定の場所に並んでいる、という状態になった。

## 今動いているルール

それから少し時間が経ったいま、ダウンロードフォルダはこういう状態になっている。

Chat側でその日のまとめを依頼する。Claudeがまとめを作る。ダウンロードする。それで終わり。

数秒後、ダウンロードフォルダからはMDが消えている。Obsidianの中のしかるべきフォルダに、種類ごとに分かれて入っている。セッション全体のまとめはまとめ用のフォルダに、アイデアメモはアイデア用のフォルダに、意思決定は意思決定用のフォルダに、ネタ起票はネタ用のフォルダに。AI同士で出てきた会話ログとか、別のAIから書き出したエクスポートも、それぞれの行き先に勝手に入っていく。AI生成のPNGはObsidianの外側のiCloud直下に並んでいく。これだけの種類のファイルが、自動で着地している。手で動かしているものはひとつもない。

「机の上が散らからない」というのは章1で書いたObsidianの恩恵だけど、その手前の「そもそも机の上に物が乗らない」というのが、この仕組みのおかげで成り立っている。最初に書いた「散らかる予感」は、手作業で予防するんじゃなくて、仕組みで予防する形で着地した。自分の意志に頼らないという意味では、意識低い系のおじさんとしては一番正しい解き方だったんだと思う。

ここまで書いてきて、章2で「Magiにテーマを依頼すると下書きが立ち上がる」みたいな話に触れたけど、あれが成立しているのは、結局この日に出来上がった仕組みが、毎日せっせと材料を集めてくれているからだ。下書きが立ち上がる仕組み単体じゃなくて、その手前で材料が勝手に溜まる仕組みがないと、たぶんあそこまで楽は出来てない。便利な道具の前に、便利になる前提の小さな仕組みを作る必要があった。

## ひとつだけ、そのとき気づいてなかったこと

実はもうひとつだけ、別の問題の影が見えていた。

ダウンロードしてきたMDをObsidianに入れる仕組みを作っているとき、Codeに別の質問もしていた。「Code側でセッションが始まったときに、自動でその過去のまとめを読みに行くようなことはできない?」と。

返ってきた答えは、「無理」だった。「自動で読みに行くことはできません。Claudeはセッション開始時にObsidianのファイルを自動で参照する手段がないです。毎回リセットされるので」ような事を言われた気がする。

ファイルを溜める仕組みはできた。ただ、AIの方は毎回ゼロからスタートする。せっかく材料を溜めても、AIの記憶のほうは持ち越せない。

このとき、自分はその意味をあまり深く考えていなかった。「じゃあCLAUDE.mdに書いておけばいいか」くらいで流していたと思う。実際、その日のうちにCLAUDE.mdから最新のまとめを読みに行く設定をCodeに入れてもらって、その場はそれで終わっていた。

ただ、AIの記憶が持ち越せない、という話は、その後も色んな場面でじわじわ効いてくる。（Claudeも日々進化していて今はメモリー機能でこの辺はある程度解消されてる気もするが）ファイルが入ってくる仕組みとは別に、「セッションが切れても話が繋がる」ための仕掛けを、別軸で考えないといけなくなった。それについてはまた別の記事で紹介する予定。

振り返ると、ダウンロードしたMDが勝手に入ってくる仕組みができた時にもう次の問題は目の前に出ていた、ということになる。

## おまけ：いま、どこに何が入ってるのか

参考までに、いま自分のところで自動で振り分けが効いているものをざっと並べておく。読み飛ばしてもらって構わない。

| ファイルの種類 | ファイル名のルール例 | どこに入るか | どんなもの |
|---|---|---|---|
| セッション全体のまとめ | `session-summary-…md` | sessions/（Obsidian内） | その日のChatでのやり取りの全体まとめ |
| 意思決定 | `decision-…md` | decisions/（Obsidian内） | 「これはこう決めた」と残しておきたい判断 |
| アイデアメモ | `idea-…md` | ideas/（Obsidian内） | ふと出てきた発想・フラッシュメモ |
| 会話ログの整理版 | `chatlog-…md` | chats/（Obsidian内） | チャットの会話ログを後から整理したもの |
| ネタ起票 | `note-idea-…md` | note/Ideas/（Obsidian内） | note記事のネタとして残したもの |
| note記事の保存 | `note_article_…md` | note-articles/（Obsidian内） | 自分が書いた・参考にした記事 |
| Codeで作ったメモやスクリプト | （規則なし、Codeが直接書き込み） | knowledge/（Obsidian内） | プロジェクトの知識ベース更新 |
